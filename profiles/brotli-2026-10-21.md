## What was disclosed (as of the date above)

A Brotli decoder bug (invalid block switch treated as "need more input") lets crafted compressed data write past an internal buffer. The Node.js advisory says this can crash the process, disclose memory or allow remote code execution when an application decompresses attacker-controlled Brotli data (`node:zlib` and equivalent APIs).

The flaw is in Google's C decoder, not in one runtime only. A copy compiled into Node, Bun, a Python wheel, Envoy, or a system `libbrotli` is in scope even when the application's own lockfile does not name `brotli`.

Lockfile scanners can miss this. Treat "Dependabot / pip-audit / OSV reported 0 findings" as a lead, not as a PASS, until each bundled copy is identified.

## How this maps to the skill

One check per target and layer:

| Layer | What to collect | PASS / FAIL |
| --- | --- | --- |
| dependency | Every lockfile, SBOM, runtime pin and vendored tree | FAIL if any listed copy is in the affected range |
| image | Package database and binaries **inside** the deployed digest | FAIL if the image still has an affected Node, wheel, libbrotli or Envoy |
| runtime | Owner-run, read-only query in the serving worker | FAIL if the running process loads an affected decoder |
| config | Whether untrusted input is decoded as Brotli | Used for `mitigated`, never as `fixed` |

A source `FROM node:24` tag is a hint, not runtime proof.

## Emergency measures are risk reduction, not fixes

Disabling Brotli **decoding** of untrusted data (reject `Content-Encoding: br` before a parser runs; turn off Envoy/Istio Brotli decompressor filters; do not auto-decode `br` in HTTP clients) is `mitigated`. Record the effective setting on every path. Encoding outgoing responses as `br`, or removing `br` from `Accept-Encoding` only, does not by itself stop a server from sending Brotli. Do not apply these automatically.

Do not write or send a crafted Brotli stream. Closure uses `vendor_patch`.

## Closing a finding under this profile

Use `verification_basis: vendor_patch`. No exploit reproduction is needed or wanted. Record all of the following:

- `package` and `fixed_build` for each copy (Node, wheel, libbrotli, Bun, Envoy)
- package-advisory evidence linked to a primary source retrieved this run
- evidence that the fixed build is installed in the deployed image digest and observed on each serving runtime
- application regression tests (valid gzip/deflate still work)

A Dockerfile pin does not close the finding until the deployed digest and the running workers show the fixed build.

The current JSON closure gate expects an image-based provenance chain. On bare-metal or managed runtimes without those fields, retain the real package/build and worker observations, disclose this schema limitation and keep automatic closure incomplete; never manufacture image or commit identifiers.

## Report wording

- Check title: `Bundled Brotli decoder versions` (add the layer in the title).
- Finding summary: name the product, the exact build, the advisory id, and whether decoding of untrusted input is on.
- Coverage gap: "SBOM not parsed" or "runtime query not available" is `BLOCKED`.
- Verdict: unchanged. A BLOCKED required check is `INCOMPLETE`. An affected build still deployed is `ISSUES_OPEN` once coverage is complete.
